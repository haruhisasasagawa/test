# 入場者プレゼント 配布可能期間 計算ツール

パフォーマンススケジュール（スクリーンのキャパ数入り）と入場者プレゼントの納品数から、
**満席になった場合にいつまで配布できるか** を算出する HTML アプリケーションです。

`present-calculator/index.html` をブラウザで開くだけで動きます。
インストール・サーバー・インターネット接続はいずれも不要で、ファイルはブラウザの外に出ません
（Excel の解析もこのファイル内の JavaScript だけで行っています）。

## スマホでの利用

**820px 以下では、スクロールする 1 枚のページではなくアプリの形に変わります。**
上にアプリバー、下にタブバー、あいだが 1 画面。1 画面 = 1 つの用途です。

| タブ | 画面 | 中身 |
| --- | --- | --- |
| 一覧 | 配布可能期間 | 1 件 2 行の詰まった一覧。押すと在庫・注意が開く |
| 掲示 | スタッフ掲示 | バックヤードに貼る形のまま |
| 今日 | その日の配布 | 準備数と上映回ごとの指示 |
| 明細 | 明細・根拠 | 横スクロールの表 |
| データ | ファイルと設定 | 読み込み・プレゼントの編集・計算条件 |

- **計算が終わるまで結果のタブには行けません。**行けないタブは薄くし、
  「データ」に赤い印を出して、次にどこを触ればいいかを示します
- できること（印刷／スマホPDF／Excel／再計算）は**アプリバー右のボタンから
  下に出るシート**にまとめました。ボタンを常時並べないぶん、一覧が長く見えます
- 画面内のビュー切替タブと下の操作バーは、下タブと重複するので出しません
- アイコンはすべて線画をそのまま埋め込んでいます（外部ファイルなし）
- `viewport-fit=cover` ＋ `env(safe-area-inset-*)` でノッチ・ホームバー・
  横向きの切り欠きを避けています
- **上下のバーの高さは実測して CSS 変数（`--ab-h` / `--tb-h`）に入れ、
  本文の余白をそれに追随させます。** 端末ごとのセーフエリアの違いや
  Safari のバーの出入りでずれるのを防ぐためです
- `visualViewport` を見て、Safari のバーで隠れる分だけ下タブを持ち上げます。
  **キーボードが出ているあいだ（150px 以上縮んだとき）は下タブを隠します**

### 指の操作

| 操作 | 動き |
| --- | --- |
| **左右になぞる** | 画面を移る（一覧 ⇄ 掲示 ⇄ 今日 ⇄ 明細 ⇄ データ） |
| **先頭で下に引っぱる** | 計算し直す。90px 引くと「離すと計算し直します」に変わります |
| **シートを下に払う** | 閉じる |
| アプリバーの見出しを押す | 先頭に戻る |
| 一覧の行を押す | 在庫・回数分・注意が開く |

なぞりの判定で気をつけたところ:

- **指を離すまで追い続ける**（`setPointerCapture`）。これが無いと、指が下タブや
  アプリバーの上を通った瞬間に取りこぼし、画面がずれたまま止まります
- **速く払ったときは短くても決める**（22px＋速さ、またはゆっくり45px）。
  距離だけで判定すると、実機の素早い指の動きが空振りします
- **画面のいちばん左 18px から始まったなぞりは見送ります**。
  iOS の「戻る」に取られる領域なので、半端に動かすより手を出さないほうが良いです
- なぞり終わりの指離しで一覧の行が開かないよう、直後の tap を無視します

- **縦のスクロールを邪魔しない**。横の移動量が縦の 1.3 倍を超えたときだけ画面移動に使います
  （`touch-action:pan-y` で縦スクロールはブラウザに任せています）
- **横に流せる表（明細・配布指示）や入力欄の上から始まったなぞりは拾いません**。
  表を横に送るつもりが画面ごと移動する、という事故を防ぎます
- **行き止まりでは引っぱりを弱く**して、これ以上ないことを指に返します
- 計算前は結果の画面へ移れないので、なぞっても止まります
- ブラウザ標準の引っぱり更新は `overscroll-behavior-y:contain` で止めています
- `prefers-reduced-motion` のときは画面の動きを出しません
- 初回だけ「左右になぞると画面を移せます」と一度出します（以後は出ません）

| 画面 | スマホでの見え方 |
| --- | --- |
| データ | 置き場が縦に 2 つ。ドラッグ＆ドロップの案内は消え、ボタンが全幅になります |
| データ | **11 列の表を 1 件 1 カードに組み替え**ます。項目名が各入力欄の上に付きます |
| 一覧 | **1 件 2 行の詰まった一覧**。押すと在庫・回数分・注意が開きます |
| 掲示 | 日付が作品名の下に回り込みます |
| 今日・明細 | **折り返さず横スクロール**（縮めて 1 文字ずつ折り返すより読めるため） |

- ボタンと入力欄は **44px 以上**（`hover:none` の端末では画面幅に関係なく確保）
- 入力欄の文字は **16px**。これ未満だと iOS が勝手に画面を拡大します
- 320px（iPhone SE）〜1400px で**横スクロールが出ないこと**を確認しています
- レイアウト切替は `@media screen and (...)` に限定しています。
  印刷時のページ幅（A4 縦は約 794px）が条件に当たって、
  **紙の掲示物までスマホ表示に化けるのを防ぐため**です

### 一覧は「一度に多く見える」ことを優先

スマホは画面が狭いぶん、1 件あたりを小さくして件数を稼ぐほうが確認は速くなります。
カードの余白と枠を捨て、罫線 1 本で区切る形にしました。実データ 27 件で
**画面に入る件数が 1.5 件 → 16 件**になっています。

| 常に出す | 押したときだけ出す | 出さない |
| --- | --- | --- |
| プレゼント名（1 行） | 残量ゲージ | 区分バッジ（見出しで分かる） |
| 作品名（1 行・小） | 在庫・回数分 | 状態記号（左の色帯と日付の色で代用） |
| **全回に配れる最終日** | 注意の全文 | 項目名のラベル |
| あと◯日 | 「席数の少ない回のみ」の期間 | |
| 注意ありの `!` 印 | | |

- **配布が終わったものは 1 行に畳んで薄く**します。確認するのは今配っているものだけです
- 区分の見出しは画面上端に貼り付き、スクロールしても今どこを見ているか分かります
- 統計の 4 つの箱は 1 行に畳みます（`27件 ／ 1週間以内 9 ／ 要確認 9 ／ 在庫 144,933`）

## 使い方

画面は **STEP 1 → 2 → 3** の 3 段だけです。

1. **STEP 1　ファイルを置く**
   大きな枠が 2 つ並んでいます。左が **① パフォーマンススケジュール**、
   右が **② 入場者プレゼント情報**。枠へドラッグするか、
   「ファイルを選ぶ」ボタンから選びます。読み込むと枠が緑になり、
   「読込済 487回」「読込済 27件」と件数が出ます。
   **②はファイルが無くても、表をコピーして貼り付けるだけで読み込めます**
   （下記「表を貼り付けて読み込む」）。
   PS はシートごとの日付（例：`2026年8月8日（土）～8月11日（火）・8月13日（木）`）を解釈し、
   スクリーン番号・キャパ数・上映回数を自動集計します。
   読み込んだ作品の一覧は「読み込んだ作品の一覧を見る」を開くと確認できます。
2. **STEP 2　プレゼントを確認する**
   取り込んだプレゼントが **区分ごとに上から** 並びます
   （入場者プレゼント → サンプリング（協賛品） → LV・イベント上映限定）。
   上のチップで区分を絞り込めます。納品数・配布開始日・対象作品などはここで直せます。
3. **STEP 3　計算する**
   起算日・想定稼働率だけ確認して「この内容で計算する」。
   細かい条件（在庫不足の回の扱い、推計する週数）は「詳しい条件」を開くと出ます。
4. **結果を 4 つのビューで確認し、印刷 / PDF保存**
   または **「Excelで書き出し」**（数式入り .xlsx。マクロ不要）

画面下には常に「計算する／印刷／Excelで書き出し」のバーが出ています。
条件を変えたら押し直してください。

## 4 つの出力

| ビュー | 用途 | 用紙 |
| --- | --- | --- |
| ダッシュボード | 事務所で全体をつかむ。**1 行 1 プレゼントの一覧＋残量ゲージ** | A4 横 |
| PDFで出す | 一覧・掲示・配布指示を紙のかたちを選んで書き出す | 選択式 |
| スタッフ掲示 | バックヤードに貼る。一覧（1 枚）と単票（1 件 1 枚）を選べる | A4 縦 |
| その日の配布指示 | 朝の準備数と、上映回ごとの配布物・確認欄 | A4 横 |
| 明細・根拠 | 数字の裏付け。週別／日別の消化推移 | A4 横 |

### 区分（入プレ／サンプリング／LV）と並び順

品目は 3 区分に分けて扱い、**すべての出力で同じ順に並べます**。

| 区分 | 意味 | 優先 |
| --- | --- | --- |
| 入場者プレゼント | お客様全員に配る。第一優先 | 1 |
| サンプリング（協賛品） | 協賛社の配布物。入プレの次に扱う | 2 |
| LV・イベント上映限定 | 該当のイベント上映回のみ | 3 |

- 入力表・ダッシュボード・掲示は、区分の見出し帯を挟んで上から順に並びます。
- **1 回の上映で複数配る場合、配布指示表の並びも入プレが先頭**になります
  （現場は上から順に手に取るため、ここが入れ替わると配り間違いになります）。
- 明細表と Excel の行順も同じです。画面と紙と Excel で行がずれません。
- ダッシュボードだけは「終了が近い順」に切り替えられます（区分をまたいで並べ直します）。

### 残量ゲージ（1 マス＝1 日）

ダッシュボードの「残り」列は **`■■■□□□…` の 14 マス**で、全回に配れる最終日までの日数を表します。
14 マス（2 週間）で満タン、期限のないものは満タン表示です。
図形ではなく文字で描いているため、プリンタの設定に関係なく印刷されます。

### PDF で出す

計算後、**「一覧をPDFで出す」**（スマホでは一覧の右下に浮かぶ **PDFで出す** ボタン）を押すと、
紙のかたちを選べます。**どれもブラウザの「PDFに保存」を使います。**

| 選択肢 | 紙 | 用途 |
| --- | --- | --- |
| スマホで読む一覧 | **90×160mm** | スタッフのスマホへ共有。拡大せずに読める |
| A4に一覧を1枚 | A4 横 | 事務所・ファイル用 |
| 掲示のかたちで出す | A4 縦 | バックヤードに貼る |
| その日の配布指示 | A4 横 | もぎり・配布担当に渡す |

選んだ紙に合わせて表示中のビューを一時的に差し替えて刷り、終わったら元の画面へ戻します。

### スマホで読む PDF の作り

**90×160mm の縦長**で配布中の一覧だけを書き出します。

A4 の掲示物をそのままスマホで開くと、画面幅に収まった瞬間に文字が豆粒になります。
そこで**紙のサイズ自体を小さくして**、1 件ずつ縦に積んでいます。
iPhone で全幅表示したとき、拡大しなくてもプレゼント名と期限が読めます。

| 載せるもの | 載せないもの |
| --- | --- |
| 配布中のプレゼント（区分の順：入プレ → サンプリング → LV） | 上映回ごとの指示 |
| 作品名・プレゼント名・**全回に配れる最終日**・状態 | 明細・根拠・在庫数 |
| 「席数の少ない回のみ」の期間 | 準備数・確認欄 |
| 配布終了したもの（名前だけ・22 文字で省略） | |
| 残数未確認の件数・一覧に載っていない件数 | |

作成は劇場の PC（Chrome / Edge）で行い、できた PDF をスタッフのスマホへ
共有してください。iPhone 単体では PDF 化できません。

区切りは罫線と記号だけで作っているので、**印刷しても背景の塗りが消えて崩れることはありません**。

### 掲示に出す日付は「全回に配れる最終日」

既定の設定（在庫不足の回のみ配布中止）では、大きいスクリーンで配れなくなった後も、
席数の少ない回では配布が続きます。そのため **配布可能最終日をそのまま掲示すると、
「まだ配れるはず」の日に大箱の回で品切れる** ことになります。

掲示には **`firstSkip` の前日＝全回に配れる最終日** を大きく出し、そのあとの
「席数の少ない回のみ」の期間は小さく併記します。実データでは両者に 1〜2 日の差が出ます。

在庫に余裕があるもの（配布終了日の指定がなく、期間内に尽きないもの）は
**日付を出しません**。この場合の最終日は推計を打ち切った地点にすぎず、掲示すると嘘になるためです。
「当面 終了予定なし」と表示します。

### 状態の伝え方（印刷は「背景の塗りが出ない」前提で設計）

Chrome / Edge の印刷は **既定で背景のグラフィックを出しません**。
状態を背景色で表すと、印刷した掲示物から状態がすべて消え、
白抜き文字の記号は白地に白で見えなくなります。

そこで状態は **記号・日本語ラベル・枠線の太さ・枠線の種類** で表し、
色は「出れば嬉しい」5 層目に格下げしています。
区分の見出し帯（画面では黒地に白抜き）も、印刷時は**塗りを捨てて上下の太罫線**に切り替わります。
黒帯のまま刷ると白地に白文字になって、見出しごと消えるためです。

| 状態 | 記号 | 画面の左帯 | 印刷の枠線 | しきい値 |
| --- | --- | --- | --- | --- |
| 配布中 | ○ | 細い実線 6px | 実線 2pt | 8 日以上 |
| 残りわずか | △ | 斜線 12px | 二重線 4pt | 4〜7 日 |
| まもなく終了 | ▲ | 横縞 20px | 太い実線 4pt | 3 日以内 |
| 期間終了・要確認 | × / ? | 点線 5px | 破線 1pt | — |

記号は輪郭から塗りへ（○ → △ → ▲）と、素直に緊急度が上がる並びにしています。

しきい値は劇場の週替わり（金曜切替）に合わせています。7 日＝次の切替を跨げるか、
3 日＝週末を跨げるか。残数のドット（●○）も図形ではなく文字で描いており、
プリンタの設定に関係なく印刷されます。

## Excel 書き出し

計算後に「Excelで書き出し」を押すと、次の 4 シートを持つ .xlsx を保存します。
マクロは使っていないため、マクロが禁止された環境でも開けます。

| シート | 内容 |
| --- | --- |
| 配布可能期間 | プレゼント別のサマリー。薄い青のセル（在庫・1人あたり・稼働率）が入力欄 |
| 明細 | 上映回ごとの引き当て計算。残数・配布可否がすべて数式 |
| 上映回 | 読み込んだパフォーマンススケジュールの上映回一覧（ピボット用の生データ） |
| 前提・注意 | 計算方法と注意点 |

在庫や稼働率を書き換えると、配布回数・残数・配布可能最終日が Excel 側で再計算されます。
明細の行数は「最後に配布できる回＋20 行」（上限 400 行）で打ち切るため、
**在庫を大きく増やした場合は行が足りなくなります**。その場合はツールから出し直してください
（該当するプレゼントには備考欄にその旨を表示します）。

## 計算の考え方

- 1 回の上映で必要な数 = **スクリーンのキャパ × 想定稼働率 × 1人あたりの配布数**（既定は満席・1人1個）。
- **その回のお客様全員に配布できない場合は、その回は配布しない**（配布ルール）。
  在庫不足の回が出たときの扱いは 2 通りから選べます。
  - `その回のみ配布中止`（既定）… 残数で賄える小箱の回は引き続き配布する
  - `そこで配布終了` … 1 回でも配布できない回が出たら以降は配布しない
- 上映回は日付＋開始時刻順に並べて先頭から在庫を引き当て、**最後に配布できた日**を「配布可能最終日」とします。
- 読み込んだスケジュールの期間より先は、**同じ編成が続く前提**で推計します
  （**既定 4 週＝1 か月先まで**。推計部分は結果表で「推計」と表示されます）。
  PS は毎週入れ替わるため、それより先は「今週の編成が続いたら」という仮定の上に乗るだけです。
  長く取るほど「当面 終了予定なし」が減って日付が出ますが、その日付の根拠は薄くなります。
  発注のリードタイムを見たいときだけ 8〜52 週に延ばしてください。

## 条件への対応

| 条件 | 対応 |
| --- | --- |
| 1. 公開から無くなるまで配布し続けるもの | 配布終了日を空欄にすると「無くなるまで」として計算 |
| 2. 週替わり（金曜始まり・土曜始まり等） | 配布開始日／配布終了日をそのまま指定（曜日は問いません） |
| 3. ライブビューイング等のイベント上映専用 | 対象作品の指定に加え、スクリーン限定・上映方式キーワード（例：`IMAX`、`舞台挨拶`）・対象時刻で絞り込み |
| 4. 全員に配布できない回は配布しない | 上記の計算ルールで実装 |
| 5. 複数のプレゼントがある（前週分の同時配布など） | 1 作品に複数行を登録。「グループ」欄に同じ名前を入れると、セットで配布できる最終日を別表で表示 |

## 表を貼り付けて読み込む

入場者プレゼント情報は、Excel ファイルが無くても **画面の表をコピーして貼り付ける**だけで
取り込めます。②の枠の「またはコピーした表を貼り付ける」を押すと入力欄が開きます。

社内サイトやメール本文の表をコピーすると、**セルの中の改行と行の区切りがどちらもただの改行に
なり、列の対応が失われます**（「作品名」が 2 行に折り返していると、次の行の作品名と区別が
つきません）。そこで列を当てにせず、次の手がかりで 1 件ずつ組み立てています。

| 手がかり | 判定 |
| --- | --- |
| `700（350）` `8,000（1000）` `23600` | 納品数（括弧内は一束の数） |
| `8/21（金）` `7月24日(金)` `7/31` | 日付。1 件目が配布開始日、続けて出たら配布終了日 |
| `無くなるまで` `調整中` `未定` | 配布終了日なし（＝無くなるまで） |
| `作品名` `納品数` `管理方法` `廃棄有無` など | 見出しなので捨てる |
| `済` `保管` `廃棄` | 管理欄の一言なので捨てる |
| ` LV　特別上映` / `サンプリング` | ここから下の区分が変わる |
| URL・`【…】`だけの行・`①②③`で始まる行・`。`で終わる行 | **直前の 1 件の備考**（次の作品名と取り違えない） |

日付の直前に並ぶ語のうち、**最後が「プレゼント名」、残りが「作品名」**になります。
Excel から直接コピーした場合（改行入りのセルが `"…"` で囲まれる形式）は、
セル内の改行を畳んでから読むので、より正確に取れます。

貼り付けると**押す前に読み取り結果の一覧が出ます**。取り違えがないか確認してから
「貼り付けた内容を読み込む」を押してください。取り込んだ後も②の表で直せます。

**割り切り**：完全な復元は原理的に不可能です。実データ（24 件・3 区分）では全件正しく
読めましたが、作品名とプレゼント名が入れ替わる可能性は残ります。
Excel ファイルがあるなら、ファイル読み込みのほうが確実です。

## 起算日より前から配っているものの扱い（重要）

**このツールは、起算日より前に配った分を差し引きません。**

- シミュレーションは **起算日以降の上映回だけ**を並べて在庫を引き当てます
  （`from = 配布開始日 > 起算日 ? 配布開始日 : 起算日`）。
- 在庫欄の数字を、そのまま **起算日時点の手持ち**として使います。

**逆算しないのではなく、できません。** 読み込む PS は今週分（例：8/7〜8/13）だけで、
7/24〜8/6 の上映回データが存在しないため、過去の消化を計算する材料がありません。

実データ 27 件のうち **16 件**が「配布開始が起算日より前」でした。
在庫欄に納品数が入ったままだと、結果は次のようにずれます。

| パウ・パトロール（納品 2,800／7/24 開始） | 全回に配れる最終日 |
| --- | --- |
| 2,800（納品数のまま） | 9/12 |
| 1,400（半分残っている場合） | 8/24 |
| 700 | 8/15 |

**19 日ずれます。** そのため、該当するプレゼントには次の 3 段構えで確認を求めます。

1. STEP 2 の上に **「N 件は配布開始が起算日より前です」** の警告帯
2. 在庫欄を橙色にし、下に **「納品数のまま／残数 確認済」** のチェック
3. 未確認のまま計算すると、ダッシュボードの注意欄・**スタッフ掲示の冒頭**・単票・Excel の備考に
   「残数未確認」と出ます（掲示は印刷しても消えません）

棚卸しして在庫欄を直したら、チェックを入れる（または「まとめて確認済みにする」）と警告が消えます。

## 入力のポイント

- **在庫欄は「計算起算日の時点で手元にある数」** を入力してください（上記のとおりです）。
- 作品名が PS の表記（`（字）`『』などが付く）と揃わない場合は、
  プレゼント行の **⚙** から対象作品を選び直してください（類似度の高い順に並びます）。
  未指定のときは作品名から自動判定します。
- 入力内容はブラウザに自動保存されます。JSON で書き出し／読み込みもできます。

## 対応している Excel の形式

- **パフォーマンススケジュール**：`SC No` / `PERFORMANCE` の見出しを持つ TOHO の PS 形式。
  A 列の `スクリーン番号 / キャパ`、上映回ごとの開始時刻列を読み取ります。
  `24:15` のような 24 時以降の表記、結合セル、**1〜7 枚のシート構成**（1 週間同じ編成でも、
  毎日違っても可）に対応します。シート数は問わず、各シートの日付ヘッダから対象日を判定します。
  読み込みが 7 日に満たない場合は、先の期間を**週単位**で繰り返して推計し、画面に注意を表示します。
- **入場者プレゼント情報**：`作品名` `プレゼント内容` `納品数` `配布開始日` `配布終了日` の見出しを持つ表。
  `LV 特別上映` `サンプリング` などの区分見出し、`2800（200）` のような一束数付きの納品数、
  追加入荷行（`5/20納品12000+2900`、`-100`）、`8/7(金)` `7月24日(金)` `無くなるまで` `調整中` などの表記に対応。

## 貼り付け式 Excel（HTMLツールを使わない版）

```
python3 make-paste-excel.py [出力先.xlsx]
```

パフォーマンススケジュールを**貼り付けるだけ**で計算できる Excel テンプレートを生成します。
マクロ（VBA）は使っていないため、マクロが禁止された環境でも開けます。

| シート | 役割 |
| --- | --- |
| 使い方 | 手順と割り切りの説明 |
| 設定 | 計算起算日・想定稼働率・曜日ごとに使う PS の指定 |
| PS1 〜 PS7 | PS の各シートをそのまま貼り付ける場所（**1〜7 枚に対応**） |
| プレゼント貼付 | **入場者プレゼント情報をそのまま貼り付ける場所** |
| 解析1〜7 | 貼り付けた PS から上映行・スクリーン・キャパ・回数を取り出す（自動） |
| 取込 | 貼り付けたプレゼント情報から納品数・日付・キーワードを取り出す（自動） |
| プレゼント | 上記から自動で入る。直したいセルは上書き可 |
| 計算 | 日付 × 上映行の展開と、在庫の引き当て（自動） |
| 結果 | プレゼントごとの配布可能最終日 |

上映行の判定は「D 列が `A` で、E〜N 列に時刻が 1 つ以上ある行」。
A 列の `スクリーン番号／キャパ`（`７/391`、`1`+改行+`88` など）から座席数を取り出し、
A 列が空の行は上の行から引き継ぎます（結合セル対策）。

### 入場者プレゼント情報の取り込み

「プレゼント貼付」シートに、`作品名` `プレゼント内容` `納品数` `配布開始日` `配布終了日` の表を
そのまま貼り付けると、「プレゼント」シートに次が自動で入ります。

| 項目 | 取り込み方 |
| --- | --- |
| プレゼント名 | そのまま |
| 納品数 | `2800（200）` の括弧内（一束の数）を落として `2800`、`初回42000` → `42000` |
| 配布開始日／終了日 | `8/7(金)` `7月24日(金)` シリアル値に対応。年は起算日から推定 |
| 配布終了日 | `無くなるまで` `調整中` は空欄（＝無くなるまで）として扱う |
| 作品キーワード | 作品名の先頭 8 文字から自動生成（記号・空白・「映画」「劇場版」を除去） |

**「一致した作品数」列を必ず確認してください。** ここが `0` のものは PS の作品名と
結びついていないので、キーワードを手で直す必要があります。実データ（27 件）では
`スパイダーマン` `ミニオンズ` `クレヨンしんちゃん` などは自動で当たりましたが、
`「パウ・パトロール」ファミリーシアター`（PS 上の作品名は `パウっと！ファミリーシアター`）
のように、名前がそもそも違うものは自動では当たりません。

なお、納品数の追加入荷行（`5/20納品12000+2900` のような、作品名が空欄の行）は
**取り込まれません**（初回の納品数のみ）。合算が必要な場合は在庫欄を手で直すか、HTML ツールを使ってください。

### PS のシート数について

PS は週によってシート数が変わります（1 枚〜7 枚）。使う枚数だけ貼り付け、
「設定」シートの曜日表で **どの曜日にどの PS を使うか** を指定してください。

| PS の構成 | 貼り付け方 | 曜日表の設定 |
| --- | --- | --- |
| 1 枚（1 週間同じ編成） | PS1 だけ | 7 曜日すべて `1` |
| 3 枚（金／土日月火木／水） | PS1・PS2・PS3 | 金`1`／土日月火木`2`／水`3` |
| 7 枚（毎日違う） | PS1〜PS7 | 曜日ごとに `1`〜`7` |

貼り付けると「設定」シートの **PS 別の読み取り状況** に上映行数と 1 日の座席数が出ます。
`0` のままなら貼り付け先が違います。

### この方式の割り切り

1. 計算できるのは起算日から **42 日（6 週）先まで**。
2. 1 日の中の順序は開始時刻順ではなく **PS の並び順**（配布可能「日」は変わりませんが、
   最終日の残数がわずかに変わることがあります）。
3. PS ヘッダの日本語日付は読み取らず、**起算日＋曜日ごとの PS 対応**で日付を作ります。
4. PS 1 シートにつき先頭 250 行・上映行 45 本まで、PS は 7 枚まで、プレゼントは 20 件まで。

厳密な計算（時刻順・任意の週数まで・作品名の自動照合）が必要な場合は HTML ツールを使ってください。

### サンプル入りファイルの生成

```
python3 make-sample.py <PS.xlsx> <入場者プレゼント情報.xlsx> <起算日 YYYY-MM-DD> [出力.xlsx]
```

テンプレートを作り、そこへ PS と入場者プレゼント情報を貼り付けた状態のファイルを出力します。
利用者のコピー＆ペースト操作を再現しているだけで、テンプレート側の数式は変えていません。
PS のシート名に曜日（金・土日月火木 など）が含まれていれば、曜日→PS の対応も自動で設定します。

### 現場の事故を防ぐための扱い

- **キャパを読み取れなかった上映回は計算から除外します。**
  0 席として扱うと「必要数 0 個なのに在庫不足」という判定になり、
  掲示の日付が壊れます（在庫が十分でも「本日から一部の回のみ」と表示される）。
  除外した回数はダッシュボードのカードに表示します。
- **その日の配布指示では「配布しない回」も表から消しません。**
  行を消すと現場では「表の作り忘れ」と読まれ、気を利かせたスタッフが配ってしまいます。
  「配布なし（満席時 ◯個 必要／在庫が足りません）」と理由つきで残します。
- **「本日は配布しません」と書くのは、その日の全回が配布不可のときだけです。**
  1 回でも配れる回があるものは「回によって配布の有無が分かれます」と表示し、
  お客様に「配布は終了しました」と案内しないよう明記します。
  同じ紙で「終了」と「配ってください」が同居すると、案内の直後に別の回で配ることになります。

## 回帰テスト

```
node test/bugcheck.mjs [パフォーマンススケジュール.xlsx]
```

過去に実際に見つかった不具合が、修正されたままかを毎回確かめます。

| 検査 | 内容 |
| --- | --- |
| A | 状態の判定が、掲示に出す日付と同じ軸か（緑の「配布中」で「明日まで」と出ないか） |
| B | 在庫 0 でも「入りが◯%以下なら」の数値が出るか（`null%` と表示されないか） |
| C | 配布開始前の日付を「〜まで配布できます」と出していないか |
| D | 推計を打ち切った日を、確定した終了日として掲示していないか |
| E | 別作品の同名プレゼントが 1 件に混ざっていないか |
| H | 「あと約◯回分」が、起算日時点の手持ちから計算されているか |
| N | 1 回に複数配るとき、入プレ → サンプリング → LV の順に並ぶか |
| O | 準備数の一覧に、内部 ID ではなくプレゼント名が出るか |
| P | 起算日より前から配っているものに「残数未確認」が立つか／起算日より前の上映回を数えていないか |
| Q | 掲示の「在庫 N 個」と「約 M 回分」の時点が揃っているか |
| R | 貼り付けた表から 24 件を正しく読めるか（区分・一束・備考の帰属・納品数なしの行） |
| S | Excel から直接コピーした引用符付き TSV も読めるか／文中の引用符を壊さないか |
| T | スマホ用 PDF が配布中のものだけを区分の順に出すか／塗りに頼っていないか |
| M | シートの日付が重なっても、同じ上映回を二重に数えないか |
