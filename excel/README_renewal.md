# シン・コンセ発注ツール（刷新版・計算エンジン）

現行版のリバースエンジニアリング設計書に沿って、**業務ロジックを踏襲したまま
データの持ち方を作り直した**ブックです。

- 生成スクリプト: `build_renewal.py`
- 生成物: `シン・コンセ発注ツール_計算エンジン.xlsx`（空）、`..._サンプル入り.xlsx`（動作確認用）

```bash
python3 excel/build_renewal.py excel/シン・コンセ発注ツール_計算エンジン.xlsx
```

## この段階でできていること

設計書 §6.4 の受入条件である5項目を算出します。

| 項目 | 出所 |
| --- | --- |
| 理論残 | ①在庫CSVのZ列（残数）をそのまま参照 |
| 購買率 | ②〜④実績CSVの販売数を、サイズ換算してから実動員で割る |
| 使用見込 | ROUNDUP(販売数見込 ÷ イールド, 0) |
| 必要数 | (ストック設定 ＋ 使用見込) − 理論在庫（設定が「実数」なら実在庫換算） |
| 発注目安 | ROUNDUP(必要数 ÷ 発注ロット, 0)　※0以下は空欄 |

**次の段階に残しているもの**：冷凍品・飲料品の分納スケジュール、常温／冷凍／飲料の3区分出力、
前回発注との差分表示、発注金額の上限アラート。

## 週次の流れ

| シート | やること |
| --- | --- |
| TOP | 自劇場・発注日・参照購買率・調整値・期間A/B/Cの実動員を入れる |
| ①在庫CSV_発注日 | 発注日時点の理論在庫CSVを貼る |
| ②③④実績CSV | 期間A／B／Cの実績CSVを貼る（購買率の元） |
| ⑤減算マスタCSV | イールド（販売商品→在庫商品の減算定義）を貼る |
| ⑥商品照会CSV | 発注ロット・仕入単価・パック入り数を貼る |
| ⑦動員計画 | 発注日からの日別動員見込みを入れる |
| **取込チェック** | **貼付の抜けや型ずれが無いか確認する（まずここ）** |
| **⑧発注計算** | **発注目安を見て発注数を決める（ここで発注）** |

## 算出式（現行踏襲）

```
調整後動員   ＝ 期間合計動員 × 動員見込み調整値
購買率       ＝ M換算販売数 ÷ 実動員       （S=0.88 / M=1 / L=1.66）
算出購買率   ＝ その在庫商品を減らす販売商品の購買率の合計
販売数見込   ＝ 調整後動員 × 算出購買率
使用見込     ＝ ROUNDUP(販売数見込 ÷ イールド, 0)
実在庫換算   ＝ カウント数 × パック入り数
必要数       ＝ (ストック設定 ＋ 使用見込) − 理論在庫（設定が「実数」なら実在庫換算）
ストック設定 ＝ ストック(ケース) × 発注ロット
発注目安     ＝ ROUNDUP(必要数 ÷ 発注ロット, 0)　※0以下は空欄
```

## 現行版から変えたところ

| 現行の負債 | 刷新版 |
| --- | --- |
| 商品マスタ 295行 × **323列**（##1〜##150 の横持ち） | **減算マスタの縦持ち**に転換。商品が増えても列を足さない |
| サイズ換算比率が2シートにベタ書き | **サイズ換算マスタ**1箇所に集約 |
| VLOOKUP列番号を `C3=1, D3=C3+1…` の数式で管理 | INDEX/MATCH の直接参照 |
| 手作業CSV貼付6箇所、順序を誤ると静かに壊れる | **取込チェック**シートで行数・型ずれ・未貼付を常時表示 |
| シート名の絵文字・全角括弧 | 丸数字＋日本語。数式内は常にクォートして参照 |

### 縦持ち転換のしくみ

減算マスタ（販売商品 × 在庫商品の明細）に計算列を2つ足しています。

- **K列「適用」**：劇場コードが0（全劇場）か自劇場なら1
- **L列「販売商品の購買率」**：購買率算出シートから引く

商品マスタの「算出購買率」は `SUMIFS(L列, F列(減算商品コード), 自分, K列, 1)` の一発で出ます。
現行の「##1〜##150 の購買率を150列ぶん SUM する」構造が、1つの SUMIFS になりました。

## 検証したこと

- LibreOfficeでの再計算で **148,096件の数式にエラー0件**
- 在庫132品目・販売アイテム180・減算マスタ361行のテストデータを投入し、
  **受入5項目すべてが132件で Python の独立再計算と完全一致**
- 途中で見つけて直した不具合
  - 動員見込み調整値が二重に掛かっていた（期間合計動員がすでに調整後だった）
  - 減算マスタから購買率を引く参照列が1つずれていた（No列を見ていた）

## 確認をお願いしたいこと

1. **イールドの多重定義**：同じ在庫商品に複数のイールドが定義されている場合、
   現行のVLOOKUP同様「最初の1件」を使っています。これで正しいか。
2. **温度区分**（常温／冷凍／飲料）：いまは商品マスタの手入力です。
   CSVの大分類・小分類コードから判定できるなら教えてください。
3. **分納の11日**：可変パラメータにしてありますが、配送サイクル固定かどうか。
4. **サイズ判定**：商品名の末尾1文字で判定しています（現行踏襲）。
   設計書 §5.2 S9 が負債として挙げているとおり、本来はマスタ項目に持つべきです。
   商品照会CSVにサイズ属性があれば切り替えます。
5. **受入条件と現行バグの関係**：設計書 §5.1 B1 で `【常温品】V4:V107` が
   全行 `#VALUE!` とされています。壊れている列は一致させようがないため、
   受入対象から外すか「現行バグ起因」として記録する運用になるかと思います。
