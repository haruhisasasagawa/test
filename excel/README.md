# 売店発注ツール（シンプル版）

在庫システムの**在庫一覧CSVを貼る → 「切れる日」を見る → 入庫日と入庫数を入れる**。
毎日やることはこれだけの Excel ワークブックです。マクロ・アドインは使いません。

- 生成スクリプト: `build_workbook.py`
- 生成物: `売店発注ツール.xlsx`（実運用用・空）、`売店発注ツール_サンプルデータ入り.xlsx`（動作確認用）
- 検証: `verify.py`（Excelの数式とは別に Python で同じ計算をやり直して突き合わせる）

```bash
python3 excel/build_workbook.py excel/売店発注ツール.xlsx <在庫一覧CSV>
python3 excel/make_sample.py            # サンプルデータ入りを作る（控えのコピーを LibreOffice で再計算して入庫の例を決める）
python3 excel/verify.py excel/売店発注ツール_サンプルデータ入り.xlsx
```

CSVを渡すと、商品マスタの初期データ（商品コード・商品名・分類・支払先・入数・単価）と仕入先の一覧を作ります。

## 4つのことしかしない

| # | やること | どこで |
| --- | --- | --- |
| 1 | 在庫CSVを貼ると、商品ごとの**今の在庫**が入る | ①在庫を貼る |
| 2 | 動員を入れると、商品ごとの**減り数のスピード**が決まる | 動員を入れる ＋ 商品マスタの「100人あたりの減り数」 |
| 3 | このまま進んで足りなくなる商品に **「○/○ に切れる」** と出る | ②発注する の「このままだと」 |
| 4 | 切れる前の日に**入庫（日付と数）**を入れると、在庫が復活して切れる日が延びる | ②発注する の黄色い2列 → 「入庫を入れると」 |

計算はこれだけです。

```
減り数/日        ＝ 100人あたりの減り数 × その日の動員 ÷ 100
その日の終わりの在庫 ＝ MAX(0, 前日の在庫 ＋ その日の入庫 − 減り数/日)   ※ 0 で止める
切れる日          ＝ 在庫が 1 個未満になる最初の日（14日先まで見る）
```

0 で止めるのは、切れた後も引き続けると「架空の赤字」ができて、入庫した分がそれに食われて見えるからです。

発注点・安全在庫・リードタイム別の計算・保管スペース・発注サイクル・消費量の推定は、
すべて外しました。「結局どこを見て発注すればいいのか」に答えるのは
**「このままだと」列の1行の文章**だけです。

## ②発注する の読み方

左から右へ読むだけで判断が終わるように並べています。

| 列 | 内容 |
| --- | --- |
| 定数(個) | 商品マスタの「定数（ケース）」× 入数。空なら在庫CSVの「規定数」 |
| 在庫(個) | 今日の在庫CSVの総数。「数えた在庫」に今日の日付で入れるとそちらを使う（緑になる） |
| 減り数/日 | これから14日の平均 |
| 切れる日 | 入庫を入れない場合に在庫が切れる日 |
| **このままだと** | 結論の文章。● 赤＝今日発注しないと間に合わない、△ 橙＝近く切れる（○/○ までに発注）、○ 緑＝14日以上もつ、？＝計算できない、－＝今日のCSVに無い |
| **入庫日（届く日）** | 黄色。▼から14日のうちのどれかを選ぶ（過去日・15日以上先は入らない） |
| **入庫数** | 黄色。「単位」の数（ケース入りはケース数、それ以外は個数）。「目安」を超える数は入らない |
| 単位・目安 | 目安＝定数まで入れるときの数（入庫日の朝の在庫から計算、切り上げ）。迷ったらこの数 |
| 2便目 入庫日・入庫数 | 任意。14日のうちに2回入るときだけ |
| **入庫を入れると** | ○ 延命できた／△ 入庫しても切れる（次の発注期限つき）、欠品の期間がある／● 入庫が遅くて間に合わない／⚠ 直すところ（直すまで発注書に載らない） |
| 14日の表 | その日の終わりの在庫。× は切れている。黄色は入庫の日 |
| 数えた在庫・数えた日 | 任意。現物を数えたときだけ |

上部には「● 今日発注」「△ 近く切れる」「⚠ 直すところ」「入庫を入れた」「発注予定額」の5つの数字と、
これから14日の動員の平均を出しています。

### 「今日発注」の判定

設定の「発注から入庫までの日数」（L/T、既定3日）を使います。

- 切れるまでの日数 ＜ L/T … ● 至急発注（今日発注しても間に合わない可能性）
- 切れるまでの日数 ＝ L/T … ● 今日発注
- それより先 … △ 「切れる日 − L/T」までに発注

## 行の並びは商品マスタの順（入力がずれない）

入庫日・入庫数は行に書きます。行の並びが日々のCSVの順だと、商品が1つ増減した翌日に
それより下の入力が全部別の商品に付け替わります。そうならないよう、②の行は
**商品マスタの行順に固定**し、マスタに無い新商品はその後ろに足しています。
行がずれるのは商品マスタの行を挿入・削除・並べ替えたときだけなので、それは
入庫を入れていない朝いちに社員がやる、と決めています（商品マスタは並べ替えできないよう保護）。

## 間違えにくくする仕組み

社歴の浅い社員・アルバイトが触る前提なので、Excel の機能だけで次を入れています。

| 事故 | 仕組み |
| --- | --- |
| 数式のセルを上書きしてしまう | 入力セル以外はロックしてシート保護（パスワード無し。校閲→シート保護の解除で外せる） |
| 入庫日を過去日・遠い先の日で入れる | 入庫日は表の見出し14日を参照するドロップダウン。他の値は入らない |
| 棚に入らない量を発注する | 入庫数の上限を「目安」（定数まで）に固定。定数が無い商品だけ 9999 まで |
| 隣の商品の行に入れてしまう | 入庫を入れた行は商品名が太字＋薄黄になる |
| 入庫日と入庫数の片方だけ入れる | 「入庫を入れると」に ⚠ で「入庫数を入れてください」等 |
| 入庫日が過ぎた行を消し忘れ、在庫を二重に数える | ⚠「入庫日が過去です（もう在庫に入っています）→ 消してください」。発注書からも外れる |
| 他劇場の入数・規定数を拾う | CSVからの数値は対象劇場の行だけから取る |
| 同じ商品コードの行が2つあるCSV | ①の上に ⚠ 件数。②には1行で出す（在庫は合算） |
| 動員の表の範囲外の日を計算する | 表は開始日から400日。範囲外なら ② とホームに ⚠ |
| 数えた在庫の日付が未来 | 数えた日は今日以前しか入らない |
| 減り数が未設定で「余裕」に見える | 「？ 減り数が未設定」と出し、緑にはしない。ホームに未設定の件数 |
| 動員が0で減らない計算になる | 上部に橙のバナー「動員が入っていません」。全行が「？ 動員が未入力」 |
| 古いCSVで発注する | 基準日が今日より2日以上前なら「⚠ 在庫が ○/○ のものです（n日前）」 |
| 別劇場のCSV・貼る場所の間違い | ①の上に「✖ まだ貼れていません」／「✔ ○行 読み込めました」。日付の違う行が混ざると ⚠ |
| 先頭ゼロ落ち（0761→761）・商品コードの数値化 | CSVシートの右端に文字に揃えた照合列（自動）。利用者は何もしなくてよい |
| 減り数の桁違い（1日あたりを100人あたりに入れる） | 商品マスタで、1日で定数以上減る計算になる減り数を橙にする |
| 色だけで判断して見落とす／モノクロ印刷 | 状態は必ず記号（● △ ○ ？ －）＋文章。14日の表も × で読める |
| 取扱商品が400件を超える | ①の上に ⚠。黙って切り捨てない |

## シート構成

| シート | 役割 | 触る人 |
| --- | --- | --- |
| ホーム | 入口。STEP 1〜3 のカードに今の数字と ✔／● | 全員 |
| ①在庫を貼る | 今日の在庫CSVを A6 に貼る | 全員（毎日） |
| ②発注する | 毎日の判断はここだけ | 全員（毎日） |
| ③発注書 | 入庫を入れた商品が集まる。仕入先を選んで印刷 | 全員（毎日） |
| 動員を入れる | 予測（読みが変わる日だけ）と実績（月1回まとめてでも可）。開始日から400日分 | 社員 |
| つかいかた | 色の意味と読み方 | 全員 |
| 月1回_1ヶ月前の在庫／2ヶ月前の在庫 | 取扱商品の入れ替わりを見る（貼らなくても動く） | 社員（月1回） |
| 商品マスタ | 定数（ケース）と100人あたりの減り数 | 社員 |
| 劇場マスタ | 劇場コード（4桁）と名前。CSV照合つき。64劇場を初期登録 | 社員 |
| 設定 | 対象劇場・発注から入庫までの日数・標準の動員・担当者・仕入先一覧 | 社員（最初に1回） |
| 計算（非表示） | 計算専用 | 触らない |

全シートの1行目に黒いアプリバー（役割と「◀ ホーム」）。タブ色はホーム黒、毎日の3枚が黄、動員と読み物が緑、それ以外は灰色。
フォントは BIZ UDPゴシック（無い環境では既定フォント）。

## 動員の決まり方

「採用する動員」は 実績 ＞ 予測 ＞ その曜日の実績平均（直近8週） ＞ 設定の標準の動員 の順です。
表の開始日は年に1回入れます（空なら今年の1月1日から400日分）。これから14日の行は薄い黄色の帯になります。
年が変わったら開始日を新しい年の1月1日にします（入力済みの行がずれるので、年に1回だけ）。

## 100人あたりの減り数の決め方

来場者100人につき何個減るか。1ヶ月の減り ÷ 1ヶ月の動員 × 100 で見当を付けて、
商品マスタに入れます。在庫CSVからの自動推定は入れていません（納品の記録が抜けると過小に出て、
かえって危ないため）。空欄の商品は「？ 減り数が未設定」と出ます。

## 注意事項

- 数式はすべて INDEX/MATCH・SUMIFS・COUNTIFS などの旧来関数です。Excel 2016 でも動きます。
- 在庫CSVはデータを **A6 セル**から貼ります。1〜4行目は案内と取込判定、5行目が見出しです。
- 在庫CSVの受け入れ容量は各10,000行、計算できる商品は400件、発注書の明細は100行、動員は400日分です。
  それぞれ `CSV_LAST` `CALC_LAST` `SHEET_LAST` `PLAN_LAST` で変えられます。
- 1行につき入庫は2便までです（1便目・2便目）。3便目は、1便目が届いて ⚠ が出てから入れ直してください。
- xlsx には計算結果を保存していません（LibreOffice で再計算して保存するとフォントとリンクが変わるため）。
  Excel は開くときに全部計算します（`fullCalcOnLoad`）。数値が出るまで数秒かかることがあります。
- ①在庫を貼る は貼り付けを邪魔しないよう保護していません。右端の3列（連番・劇場コード・商品コード）は
  数式なので消さないでください。消えたら `build_workbook.py` で作り直します。
- 日付書式の曜日（`aaa`）は使わず、`CHOOSE(WEEKDAY(...))` で組み立てています。
- 金額はすべて税抜です。
- サンプルデータの基準日は 2026/5/1 なので、開くと「在庫が古い」の警告が出ます。動作確認用です。
- 以前の版（定数管理＋消費量推定＋ダッシュボードの17シート構成）は `legacy/` に残してあります。
