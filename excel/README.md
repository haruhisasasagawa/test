# 売店発注ツール（Excel版・全劇場対応）

在庫システムから出力した**在庫一覧CSVを貼り付けるだけ**で、劇場ごとの理論値在庫から
発注が必要な商品と推奨発注数を自動算出するExcelワークブックです。

- 生成スクリプト: `build_workbook.py`
- 生成物: `売店発注ツール.xlsx`（実運用用）、`売店発注ツール_サンプルデータ入り.xlsx`（動作確認用）

```bash
python3 excel/build_workbook.py excel/売店発注ツール.xlsx <在庫一覧CSV>
```

CSVを渡すと、その内容から商品マスタの初期データ（商品コード・商品名・分類・支払先・入数・単価）を作ります。

## どこを見て発注するのか

シート名の丸数字を**①から順にたどれば発注が終わります**。
発注そのものは「⑥発注書」を印刷して送るだけです。

| シート | 毎日やること |
| --- | --- |
| ①在庫CSV_2ヶ月前 | 2ヶ月前の1日時点の在庫一覧CSVを貼る |
| ②在庫CSV_当日 | 今日の在庫一覧CSVを貼る |
| ③動員計画 | 来場者の読みを入れる（読みが変わる日だけでよい） |
| ④ダッシュボード | 劇場全体の状況を図で眺める |
| ⑤タイムテーブル | 在庫の持ち日数を見ながら発注数を決める |
| **⑥発注書** | **ここを印刷して発注する（終着点）** |
| 発注管理 | 発注した内容と入荷を記録する |

準備として一度だけ触るシート：設定・商品マスタ・劇場マスタ・規模マスタ・季節係数マスタ。
裏方：発注計算（すべての計算の元）・全劇場サマリ。

## 2つの在庫CSVで発注漏れを防ぐ

在庫システムから出力する在庫一覧は、取扱商品のラインナップが期中で変わります。
そこで**当月を含まない直近2ヶ月前の1日時点**と**当日**の2時点を貼り付け、
その**和集合**で商品行を作ります。片方にしか無い商品も必ず計算対象に入るため、
入れ替わった商品が発注リストから抜け落ちません。

ダッシュボードの「商品の入れ替わり」ブロックで、
新商品・終売候補・マスタ未登録・在庫マイナスの件数を確認できます。

## 動員予測はどこに入れるか

**③動員計画**シートが唯一の入力場所です。当日基準日から90日分の日付が並んでいるので、
「予測来場者数」に読みを入れます。**空欄の日は劇場の標準来場者数**（規模マスタ／劇場個別）が
自動で使われるので、**大型作品の公開週など読みが変わる日だけ**入力すれば十分です。

季節係数は季節係数マスタから日付ごとに自動で決まり、予測来場者数に掛かります。
発注計算は「当日基準日から リードタイム＋発注サイクル 日分」の動員合計を使うので、
公開週をまたぐ発注では自動的に多めに算出されます。

「主な作品・備考」欄は自由入力です。あとで実績を振り返るときの手がかりになります。

## タイムテーブル画面

発注の判断は、突き詰めると**時間の勝負**です。「在庫があと何日もつか」と
「リードタイムに間に合うか」の比較でしかありません。ところが在庫表は数量を並べるだけなので、
この時間の余裕がまったく見えません。

そこでタイムテーブル画面は、在庫を**上映スケジュール表の形式**で見せます。
横軸は当日基準日からの14日間で、各商品の帯が在庫の持ち日数です。

| 表示 | 意味 |
| --- | --- |
| 帯の長さ | 在庫が尽きるまでの日数 |
| 緑 | 余裕 |
| 橙 | 発注サイクル内に在庫が切れる（要発注） |
| 濃い赤 | 今日発注しないとリードタイムに間に合わない |
| バター色の続き | 発注数を入れたときに伸びる分 |
| 黒い縦罫線 | 発注デッドライン（在庫が尽きる日 − リードタイム） |

画面の一番上には結論だけを大きく置いています。「何品目に発注が必要か」を読めば、
その日の作業量が決まります。

**発注数** 列（黄色）に数量を入れると、伸びた分が帯の先にその場で足されるので、
発注の効果を確かめながら数量を決められます。金額もその場で積み上がります。

帯は条件付き書式で描いているので、追加のアドインやマクロは不要です。
色だけに頼らないよう、状態は「状態」列に文字でも表示しています。

## ダッシュボード画面

数字の羅列ではなく、**図で状況を掴む**ことを目的にした画面です。
細い列を並べた方眼をキャンバスにして、結合セルでブロックを組んでいます
（Excelのダッシュボードでよく使われる作り方）。すべてグラフとセル塗りだけで、
マクロもアドインも使いません。

| ブロック | 何が分かるか |
| --- | --- |
| 信号ボード | 欠品リスク／要発注／余裕の品目数と推奨発注額。色の大きさで危険度が先に目に入る |
| 在庫状況の内訳（ワッフル） | 100マスで全体の構成比。赤がどれだけ占めるかが面積で分かる |
| 在庫日数の分布 | どこに山があるか。棒の色が重症度（赤＝切れかけ、緑＝余裕） |
| 商品分類 × 状態 | どの分類が危ないかのヒートマップ。在庫金額はデータバーで大小を表示 |
| 仕入先別 推奨発注額 | どこにいくら発注することになるか |
| 今後14日の入荷予定 | 納品予定日ごとの金額。色が濃い日ほど入荷が集中している |
| 今後14日の動員予測 | 動員計画の数字。山の来る日に在庫が持つかを確かめる |
| 商品の入れ替わり | 新商品・終売候補・マスタ未登録・在庫マイナスの件数（発注漏れの目印） |

### なぜこの構成にしたか

在庫管理ダッシュボードの定石として、**在庫日数（days of cover）とリードタイムの比較**が
最も行動につながる指標とされています。「在庫日数28日・リードタイム84日」なら、
このままでは56日間欠品する、という読み方ができるためです。
このツールもその考え方を軸に、信号ボードと在庫日数の分布を最上段に置いています。

ワッフルチャートとヒートマップは条件付き書式だけで作れるため、
追加のツールなしにこの表現が使えます。

参考にした資料は README 末尾に挙げています。

## 設計の要点

### 1. 全劇場を1ファイルで持ち、対象劇場を切り替えて使う

在庫CSVは全劇場分をまとめて貼り付けられます。「設定」シートで対象劇場コードを選ぶと、
発注計算とダッシュボードがその劇場のものに切り替わります。劇場横断の状況は「全劇場サマリ」で確認します。

### 2. 劇場の規模差は「規模3段階＋個別上書き」で吸収する

安全在庫日数・発注サイクル・想定来場者数は、規模区分（大/中/小）ごとの標準値を使います。
特定の劇場だけ変えたい場合は劇場マスタの個別欄に入力すると、そちらが優先されます。
75サイトを1件ずつ設定しなくても、標準3段階で運用を回せます。

### 3. 劇場特性（1杯売り／ドリンクバー）はPIプロファイルで吸収する

PI値（来場者100人あたりの消費数）は「規模区分_ドリンク提供方式」の6プロファイル別に
商品マスタで持ちます。劇場マスタで規模と提供方式を選ぶとプロファイルが自動で決まり、
対応するPI値列が参照されます。

さらに、**発注計算の対象商品は在庫CSVの実データから作られます**。
ドリンクバー方式の劇場ではS/Lカップがそもそも在庫一覧に出てこないため、
取扱商品の違いは設定しなくても自動的に反映されます。

### 4. 期中の商品入れ替えに対応する

当日CSVと2ヶ月前CSVの**和集合**で商品行を作るため、期中に入れ替わった商品も取りこぼしません。
「状態」列で以下を自動判定します。

| 表示 | 意味 |
| --- | --- |
| 新商品 | 当日CSVにあり、2ヶ月前CSVに無い |
| 終売候補 | 2ヶ月前CSVにあり、当日CSVに無い |
| マスタ未登録 | 商品マスタに登録が無い（L/T・ロット・PI値が既定値のまま） |
| 在庫マイナス | 理論値在庫がマイナス（納品の未計上などデータ側のずれ） |
| PI値未設定 | PI値予測基準なのにPI値が空欄 |

### 5. 繁忙期・閑散期の調整

季節係数マスタで月別の係数を設定できます。特定期間だけ変えたい場合は
「特別期間」に開始日・終了日・係数を登録すると、その期間は月別係数より優先されます
（大型作品の公開週など）。期間が重なる場合は係数が最大の行が使われます。

## 計算式

```
理論値在庫     ＝ 在庫CSVの「総数」（＝在庫数ケース×入数＋在庫数バラ）
期間消費数     ＝ 2ヶ月前の在庫 ＋ 期間納品数 － 当日在庫
実績消費/日    ＝ 期間消費数 ÷ 期間日数
PI予測消費/日  ＝ 動員計画のカバー期間の来場者合計 ÷ カバー日数 × PI値 ÷ 100
安全在庫数量   ＝ 採用消費/日 × 安全在庫日数
発注点         ＝ 採用消費/日 ×（リードタイム ＋ 発注サイクル）＋ 安全在庫数量
推奨発注数     ＝ 発注点 － 当日理論在庫 － 発注残
推奨発注数(ケース) ＝ 推奨発注数 ÷ 入数 を最低ロット単位に切り上げ
```

「採用消費/日」に何を使うかは設定シートの**算出基準**で切り替えます。

| 算出基準 | 採用消費/日 | 想定する使い方 |
| --- | --- | --- |
| 実績消費 | 在庫2時点の差から算出 | 通常週の標準運用 |
| PI値予測 | 来場者予測 × PI値 | 大型作品の公開週など、実績が当てにならない週 |
| 規定数 | （発注点に規定数をそのまま使用） | CSVの規定数を基準在庫として運用する場合 |
| 最大値 | 実績とPI予測の大きい方 | 欠品を避けたい繁忙期 |

期間納品数は発注管理シートの「入荷済み」レコードから集計します。
未入荷（発注状況＝発注済）の数量は「発注残」として推奨発注数から差し引かれるため、二重発注を防げます。

## 注意事項

- 数式はすべて INDEX/MATCH・SUMIFS などの旧来関数で記述しています。
  XLOOKUP等の新関数は使っていないため、古いExcelでも動作します。
- 在庫CSVの劇場コードは「0761」のような**先頭ゼロ付きの文字列**です。貼り付け後、
  設定シートの「当日CSV該当行数」が0のままなら、コードが数値に変換されています。
  CSV列を文字列として取り込むか、劇場マスタ側のコードを実際の値に合わせてください。
- 在庫CSVの受け入れ容量は各10,000行（75劇場×約130商品を想定）です。
  超える場合は `build_workbook.py` の `CSV_LAST` を変更して再生成してください。
- 発注計算・タイムテーブルの行数は400商品までです（`CALC_LAST`）。
- 発注書の明細は100行までです。
- 動員計画は当日基準日から90日分です（`PLAN_LAST`）。
- 日付書式に曜日（`aaa`）を使うと環境によっては日付表示が壊れるため、
  日付は `yyyy/m/d` とし、曜日が要る場所は `CHOOSE(WEEKDAY(...))` で別に組み立てています。
- 金額はすべて税抜です。
- 初期の商品マスタはサンプルCSV（132品目）から作成しています。
  L/T日数は3日、最低ロットは1、PI値は空欄が初期値です。運用前に実際の値へ更新してください。
- `売店発注ツール_サンプルデータ入り.xlsx` は3劇場（大規模・1杯売り／中規模・ドリンクバー／
  小規模・1杯売り）ぶんの在庫CSV、90日分の動員計画、発注履歴14件を入れた動作確認用です。
