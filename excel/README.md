# 売店発注ツール（Excel版・全劇場対応）

在庫システムから出力した**在庫一覧CSVを貼り付けるだけ**で、劇場ごとの理論値在庫から
発注が必要な商品と推奨発注数を自動算出するExcelワークブックです。

- 生成スクリプト: `build_workbook.py`
- 生成物: `売店発注ツール.xlsx`（実運用用）、`売店発注ツール_サンプルデータ入り.xlsx`（動作確認用）

```bash
python3 excel/build_workbook.py excel/売店発注ツール.xlsx <在庫一覧CSV>
```

CSVを渡すと、その内容から商品マスタの初期データ（商品コード・商品名・分類・支払先・入数・単価）を作ります。

## 毎日やることは3枚だけ

シート名を「何をするか」にしてあります。①②③を左から順にやれば、その日の発注は終わります。

| シート | やること |
| --- | --- |
| **①今日の在庫を貼る** | 在庫一覧CSVを A6 セルに貼り付ける。上部に「✔ ○○行 読み込めました」と出る |
| **②発注数を決める** | 帯を見ながら黄色の「発注数」に数字を入れる |
| **実棚を入れる** | ★が付いた商品だけ現物を数えて入れる（十数品目） |
| **③発注書** | 発注先を選んで印刷する |

たまに触るシートは、名前に頻度を書いてあります。

| シート | 頻度 |
| --- | --- |
| 月1回_1ヶ月前の在庫を貼る | 月に1回、1ヶ月前の在庫一覧CSVに貼り替える |
| 月1回_2ヶ月前の在庫を貼る | 月に1回、2ヶ月前の在庫一覧CSVに貼り替える |
| 随時_動員を入れる | 動員の実績（月1回まとめてで可）と、公開週などの読み |

読み物は「はじめに」と「発注のしくみ」の2枚（タブが緑）。
管理者向け：ダッシュボード・発注管理・商品マスタ・定数マスタ・設定。
計算専用の「発注計算」「全劇場サマリ」は**非表示**にしてあります（触る必要がないため）。

## マスタは2枚だけ

人が決める数字が分散すると「どこを直せばいいか」が分からなくなるため、
**劇場・規模区分・月別係数・特別期間を「定数マスタ」1枚に集約**しています。

| 定数マスタのブロック | 内容 |
| --- | --- |
| ① 劇場マスタ | 劇場コード・劇場名・規模区分・ドリンク提供方式。個別に上書きしたい定数もここ。収容ケース数は⑤から自動集計 |
| ② 規模区分の標準値 | 大／中／小それぞれの来場者数・安全在庫日数・発注サイクル |
| ③ 月別の係数 | 12ヶ月ぶんの係数 |
| ④ 特別期間 | 大型作品の公開週など。月別の係数より優先される |
| ⑤ 保管設備 | 冷蔵庫・冷凍ストッカー・バックヤード棚などの台数と1台あたり収容ケース数 |
| ⑥ 発注サイクル | 商品グループごとの発注曜日。○を付けた回数から「サイクル日数＝7÷週の回数」を出す |

6ブロックを横に並べているため、シート先頭に配置（① B列／② N列／③ T列／④ W列／⑤ 110行目／⑥ AB列）を書いています。

## 劇場マスタの初期登録

公式サイト（tohotheater.jp）の各劇場ページURLで確認できた **64劇場** を初期登録済みです。
URLに出てくる3桁コード（例：`/theater/076/` → 新宿＝076）と劇場名を対にしています。

- **劇場コードは暫定値です。** 自社の在庫CSVは4桁（新宿＝`0761`）で、公式3桁＋`1` の形になっています。
  実データが1劇場ぶんしかないためこの規則で展開しており、**M列「CSV照合」** で全劇場ぶん検証できます。

  | M列の表示 | 意味 |
  | --- | --- |
  | ✔ 一致 | CSVに同じコードがあり、劇場名も一致 |
  | △ CSVでは○○ | コードは当たったが劇場名が違う |
  | ✖ CSVに無し | そのコードはCSVに存在しない → 自社コードに直す |

- **規模区分（大／中／小）も暫定値です。** スクリーン数・座席数から機械的に置いただけなので、
  実際の動員・売上に合わせて直してください。判断材料として、備考欄に都道府県・スクリーン数・座席数・公式コードを入れてあります。
- **ドリンク提供方式** は既定で全劇場「1杯売り」です。ドリンクバーの劇場は選び直してください。
- 公式の劇場数は77サイト（2026/6/29 コーポレートプロファイル、共同経営5サイト含む）です。
  差分の劇場は空行に追記してください。

もう1枚は商品マスタ（リードタイム・最低ロット・保管区分・発注グループ・PI値）です。

## 「発注のしくみ」シート

定数がどこにあるのか、そこから発注数がどう出るのかを1枚の図にしたシートです。
最初に1回だけ読めば、あとは②だけ見れば発注できます。

- **1. 定数はどこにあるか** … 決めておくこと／置き場所／ブロック／**今の値**／見直す頻度／誰が決める、の一覧。
  「今の値」は選択中の劇場の現在値を実際に数式で引いているので、説明ではなく現物を見ることになります。
- **2. その定数から、発注数が出るまで** … 商品を1つ選ぶと、その商品の実数字で
  `1日に減る数 → リードタイム → 発注サイクル → 安全在庫 → 発注点 → 在庫 → 発注残 → 発注数`
  を上から順に追えます。各行に「どこから来た数字か」（どのシートのどのブロックか）が付きます。
  空欄のままなら、**いま一番発注が必要な商品**を自動で表示します。
- **同じことを図にすると** … 帯全体が発注点。緑＝いまの在庫、黄＝発注済みで届く分、赤＝今日発注する分。

## 発注サイクルは商品グループごと

冷凍品とドリンクシロップは週3回（月・水・金）、常温包材は木曜の1回だけ、というように
便の頻度は商品によって違います。定数マスタ⑥にグループごとの曜日を登録し、
商品マスタの「発注グループ」で商品を紐づけます。

| 発注グループ | 曜日 | サイクル日数 |
| --- | --- | --- |
| 冷凍品 | 月・水・金 | 2.3日 |
| ドリンクシロップ | 月・水・金 | 2.3日 |
| 常温包材 | 木 | 7.0日 |
| その他常温 | 木 | 7.0日 |

サイクル日数は発注点に直接効きます（`発注点 ＝ 消費/日 ×（L/T ＋ サイクル）＋ 安全在庫`）。
週1回しか発注できない包材は、そのぶん多めに持つ計算になります。
グループ未設定の商品は、劇場の既定サイクル（定数マスタ②）にフォールバックします。

### 「今日はどれを発注する日か」を画面に出す

便が商品ごとに違うと「今日そもそも発注できるのか」が分からなくなるため、
「②発注数を決める」の最上部に出しています。

```
今日 5/1（金）に発注できるのは　冷凍品・ドリンクシロップ
次に発注できる日　常温包材 は 5/7（木）から　／　その他常温 は 5/7（木）から
```

明細側でも、**発注グループ列が薄いグレーの行は今日が発注日ではない商品**です。
帯が赤いのにグレーの行は「次の便まで在庫が持たない」という意味なので、早めの相談対象になります。

次の発注日は定数マスタ⑥の補助列（AN〜AX）で、基準日から0〜6日先を順に見て
○の付いた最初の曜日を取る形で求めています。

## 商品ごとの最大保管数（定数）

**発注できる量は、その商品を棚に何ケース置けるかで決まります。**
商品マスタの「最大保管数(ケース)」に入れると、発注数がその数を超えなくなります。

| 列 | 内容 |
| --- | --- |
| 最大保管数(ケース) | その商品を置ける上限。**入力** |
| 目安(自動) | 発注点をケース単位に切り上げた数。**これ未満だと切らしやすい** |

132商品ぶんの定数を勘で決めるのは無理なので、**隣に目安を出しています**。
消費量・リードタイム・発注サイクルから逆算した「最低これだけ要る」ケース数です。

### 3つの発注方式

設定シートの**発注量の決め方**で切り替えます。いずれも最大保管数は超えません。

| 方式 | 発注量 | 消費量を使うか |
| --- | --- | :---: |
| **定数方式（毎回、定数まで補充）**（既定） | 定数 − 在庫 − 発注残 | **使わない** |
| 定数方式（発注点を割ったら補充） | 発注点を割っていれば 定数 − 在庫 − 発注残 | 使う |
| 発注点方式（足りない分だけ） | MIN(発注点との差, 定数との差) | 使う |

サンプルでの合計は 689 / 603 / 526 ケースでした（3方式とも全137行を独立に検算済み）。

**既定を「毎回、定数まで補充」にしているのは、消費量の計算を一切使わないからです。**
理由は次のとおりです。

### 「定数が発注点より小さい」の警告

**最大保管数 < 発注点** の商品は、棚を満杯にしても次の便まで在庫が持ちません。
状態欄に警告が出て、ダッシュボードにも件数が出ます。

打ち手は3つです。棚を広げる／その商品の発注頻度を上げる（定数マスタ⑥）／
その商品だけ小分けで別便にする。**放置すると必ず欠品します。**

なお在庫CSVの「規定数」列に値が入っていれば、商品マスタが空欄のときの代わりに使います
（今回いただいたCSVでは全商品が空でした）。

## 保管スペースの制約

**発注できる量は、置ける量で決まります。** 冷凍ストッカーが20ケース分しかないのに
45ケース発注しても、現場は受け取れません。

⑤保管設備に設備を登録すると、常温／冷蔵／冷凍それぞれの収容ケース数が自動で集計され、
「②発注数を決める」の右上に**埋まり具合**が出ます。

```
常温 67%          冷蔵 72%          冷凍 92%
1,619 / 2,400ケース  517 / 720ケース   293 / 320ケース
```

計算式は `(今の在庫のケース数 ＋ いま入力している発注ケース数) ÷ 収容ケース数` です。
85%を超えるとオレンジ、100%を超えると赤くなります。
**発注数を入れながら埋まり具合が動く**ので、入りきるかを確かめながら数量を決められます。

商品ごとの保管区分（常温／冷蔵／冷凍）は商品マスタで選びます。

## 理論値だけで発注しない（実棚を入れる）

在庫CSVの数は**理論値**（仕入 − 減算）です。ロス・破損・減算マスタのズレ・納品の未計上で
現物とずれ、**そのズレはそのまま発注数のズレになります**。

サンプルデータでの実例です。理論値がマイナスの商品を数え直すと、発注量がこれだけ変わります。

| 商品 | 理論値 | 実棚 | 理論値のまま発注 | 実棚を入れて発注 |
| --- | ---: | ---: | ---: | ---: |
| サッポロポテトバーベＱシーズニング | −32 | 6 | 48ケース | **0ケース** |
| シネマイク 塩キャラメル味シーズニング | −31 | 7 | 60ケース | **9ケース** |
| マリオ Ｄカップ ヨッシー | −16 | 6 | 10ケース | **5ケース** |

「実棚を入れる」シートに**数えた数**と**カウント日**を入れると、その商品はそちらを使って計算します。
カウント日が当日基準日より前の行は使いません（前に数えた数が残って発注量を狂わせるのを防ぐため）。

### 全部数えなくていい

132商品を毎日数えるのは不可能なので、**今日数えるべき商品に★が付きます**。

| 数える理由 | 条件 |
| --- | --- |
| ★ 理論値がマイナス | あり得ない値。納品未計上が濃厚で、放置すると大量発注になる |
| ★ 今日発注する商品 | 今日が発注日のグループで、推奨発注数が出ている（間違えると即コストになる） |
| 金額が大きい | 在庫金額の上位10品目 |

上部に「不足（ロス）」と「超過（未計上）」を**分けて**集計します。
合算すると相殺されて何も見えなくなるためです。マイナス側は廃棄・破損・減算のズレ、
プラス側は納品がシステムに入っていない疑いで、打ち手が違います。

## 消費量の計算は、当てにしすぎない

```
期間消費数 ＝ 前回在庫 ＋ 期間の納品 − 当日在庫
```

この式は、**期間中の納品がすべて発注管理シートに記録されている**ことが前提です。
記録が抜けると、その分がまるごと消費から落ちて**消費量が過小に出ます**。
過小な消費量は過小な発注点になり、静かに欠品します。

サンプルデータでは、**入荷記録がある商品は137商品中3商品だけ**でした。
2ヶ月ぶんの納品を1件も漏らさず記録し続けるのは、現実的な運用ではありません。

だから既定は**定数方式（毎回、定数まで補充）**です。

```
発注数 ＝ 定数 − 今の在庫 − 発注済み       ← 消費量が一切出てこない
```

消費量が使われるのは次の2か所だけで、どちらも欠かせない場所ではありません。

- 商品マスタの「目安(自動)」列 … 定数をいくつにするか決めるときの参考値
- 発注点方式・定数方式（発注点を割ったら補充）を選んだとき

設定シートの**入荷記録のある商品数**で、消費量がどれだけ当てになるか確認できます。

## 在庫CSVを3枚貼るのは「取扱商品の確認」のため

**消費量を出すためではありません。** 取扱商品は半年ごとに入れ替わるので、
当日のCSVだけを見ていると「先月まで扱っていた商品」が発注リストから静かに消えます。

当日・1ヶ月前・2ヶ月前の3枚を突き合わせ、そのどれかに載っている商品を
すべて計算対象にします（和集合）。**2枚だと「1ヶ月前にだけ扱っていた商品」が抜け落ちます。**

1ヶ月前・2ヶ月前のシートを開くと、上部にその結果が出ます。

| シート | 内容 |
| --- | --- |
| ①今日の在庫を貼る | 当日。これが理論在庫になる |
| 月1回_1ヶ月前の在庫を貼る | 1ヶ月前の1日 |
| 月1回_2ヶ月前の在庫を貼る | 当月を含まない2ヶ月前の1日 |

### 取扱の変化が6通りに分かれる

どの枚に載っていたかの組み合わせで、入れ替わりの中身まで分かります。

| 2ヶ月前 | 1ヶ月前 | 当日 | 判定 |
| :---: | :---: | :---: | --- |
| ○ | ○ | ○ | 継続 |
| ✕ | ✕ | ○ | 新商品（今月から） |
| ✕ | ○ | ○ | 新商品（先月から） |
| ○ | ○ | ✕ | 終売（今月から） |
| ○ | ✕ | ✕ | 終売（先月から） |
| ○ | ✕ | ○ | **復活（先月は無し）** ← 欠品していた疑い。要確認 |

「復活」は2枚構成では検出できません。1ヶ月まるごと在庫が無かったのに今月は在庫がある、
という状態なので、長期欠品か棚卸漏れの可能性があります。

ダッシュボードの「商品の入れ替わり」ブロックに、それぞれの件数が出ます。

### 消費の急変も分かる

3時点あると、**直近1ヶ月**と**その前1ヶ月**の消費量を別々に出して比較できます。

```
（終売）季節限定ドリンク      前1ヶ月 0.97 → 直近1ヶ月 4.00  +313%
シネマイク トリュフバターシーズ  前1ヶ月 1.90 → 直近1ヶ月 5.10  +168%
```

2ヶ月をならした平均だけを見ていると、直近で跳ねた商品が埋もれます。
設定シートの**実績消費の集計期間**で `2ヶ月`（ならして安定・推奨）と
`直近1ヶ月`（最近の動きに追随）を切り替えられます。

## 毎日カウントは要らない

購買率を「その日の消費 ÷ その日の動員」で出すなら、毎日の突き合わせが必要になります。
このツールは **「期間の消費合計 ÷ 期間の動員合計」** で出しているので、日ごとの対応づけは不要です。
在庫2時点の差が、そのまま期間の消費合計になっているためです。

さらに、**発注数に効くのは購買率の絶対値ではなく「これからの動員 ÷ 期間の平均動員」の比だけ**です。
実測PI値は途中の表示でしかなく、式を展開すると消えます。

```
1日に減る数 ＝ 実測PI値 × これからの動員 ÷ 100
           ＝ 実績消費 ×（これからの動員 ÷ 期間の平均動員）   ← PI値が消える
```

検証として、動員の数字（実績・予測とも）をまとめて2倍にして再計算しました。

| | 元 | 動員を2倍 |
| --- | ---: | ---: |
| 期間の平均動員 | 1,754 | 3,509 |
| 実測PI値（129商品） | 0.738 など | **半分になる** |
| 採用消費/日 | 27.78 | 27.78（差は最大0.0017%、ROUNDの誤差のみ） |
| **発注ケース数** | — | **1品目も変わらない** |

### 入力の手間

| 入れるもの | 頻度 | 入れないとどうなるか |
| --- | --- | --- |
| **当日の在庫CSV** | 発注する日ごと | 発注できない。これは発注そのものに必要な作業 |
| 1ヶ月前・2ヶ月前の在庫CSV | 月1回 | 消費量が出ない |
| 動員の実績 | 月1回まとめてで可 | 曜日ごとの差が出ず、平日を多めに見積もる |
| 動員の予測 | 読みが変わる日だけ | その曜日の実績平均で代用される |
| 実在庫（数えた数） | ★が付いた商品だけ | 理論値のズレがそのまま発注数のズレになる |
| 購買率（PI値） | **入力不要** | 在庫の減りと動員から自動で出る |

在庫CSVは発注する日に貼りますが、それは発注そのものに必要な作業です。
**動員に連動させるために増える手間はありません。**

## 動員はどこに入れるか

**随時_動員を入れる**シートが唯一の入力場所です。**予測と実績の両方**をここに入れます。

| 列 | 入れるもの | 頻度 |
| --- | --- | --- |
| 予測来場者数 | 読みが変わる日だけ | 大型作品の公開週など |
| 実績来場者数 | 実際に来た数 | 毎日でも、月1回まとめてでも |

### 実績を入れると何が変わるか

計算だけなら実績が無くても動きますが、入れると3つ効きます。

**1. 期間の平均動員が自動で出る**（実測PI値の分母）。手入力の打ち間違いが消えます。
サンプルでは手入力の想定値 2,750 に対し、実績からの自動計算は **1,758** でした。
56%ずれており、そのぶん全商品の発注量がずれます。

**2. 曜日ごとの平均が出る。** 予測を入れていない日の見積もりが、
劇場の標準来場者数ではなく**その曜日の実績平均**になります。ここがいちばん効きます。

| 曜日 | 実績平均 | 予測なしの日の採用値（係数1.2） | 旧仕様（標準3,000×1.2） |
| --- | ---: | ---: | ---: |
| 火 | 1,067 | 1,281 | 3,600 |
| 水 | 1,000 | 1,200 | 3,600 |
| 日 | 3,098 | 3,718 | 3,600 |

映画館は曜日で動員が3倍近く違うので、全曜日に同じ標準値を当てると平日は大幅な過剰発注になります。

**3. 予測と実績のズレが見える。**「予測とのズレ」列に出ます。±20%を超えた日は色が付きます。

### 日付がずれない作り

日付は「**表の開始日**」（1回だけ入力）から生成します。当日基準日に紐づけると、
CSVを貼り替えるたびに行がずれて、入力済みの予測が別の日の値になってしまうためです。
表は開始日から220日分あります。

### 採用来場者数の決まり方

```
実績がある日          → 実績をそのまま（季節係数は掛けない。もう入っているため）
実績がなく予測がある日 → 予測 × 季節係数
どちらもない日        → その曜日の実績平均 × 季節係数
実績が1日もない曜日    → 劇場の標準来場者数 × 季節係数
```

季節係数は定数マスタ③④から日付ごとに自動で決まります。
発注計算は「当日基準日から リードタイム＋発注サイクル 日分」の動員を見るので、
公開週をまたぐ発注では自動的に多めに算出されます。

「主な作品・備考」欄は自由入力です。あとで実績を振り返るときの手がかりになります。

## 「②発注数を決める」画面

発注の判断は、突き詰めると**時間の勝負**です。「在庫があと何日もつか」と
「リードタイムに間に合うか」の比較でしかありません。ところが在庫表は数量を並べるだけなので、
この時間の余裕がまったく見えません。

そこでこの画面は、在庫を**上映スケジュール表の形式**で見せます。
横軸は当日基準日からの14日間で、各商品の帯が在庫の持ち日数です。

| 表示 | 意味 |
| --- | --- |
| 帯の長さ | 在庫が尽きるまでの日数 |
| 緑 | 余裕 |
| 橙 | 発注サイクル内に在庫が切れる（要発注） |
| 濃い赤 | 今日発注しないとリードタイムに間に合わない |
| バター色の続き | 発注数を入れたときに伸びる分 |
| 黒い縦罫線 | 発注デッドライン（在庫が尽きる日 − リードタイム） |

画面の一番上には結論だけを大きく置いています。「何品目に発注が必要か」を読めば、
その日の作業量が決まります。

**発注数** 列（黄色）に数量を入れると、伸びた分が帯の先にその場で足されるので、
発注の効果を確かめながら数量を決められます。金額もその場で積み上がります。

帯は条件付き書式で描いているので、追加のアドインやマクロは不要です。
色だけに頼らないよう、状態は「状態」列に文字でも表示しています。

## ダッシュボード画面

数字の羅列ではなく、**図で状況を掴む**ことを目的にした画面です。
細い列を並べた方眼をキャンバスにして、結合セルでブロックを組んでいます
（Excelのダッシュボードでよく使われる作り方）。すべてグラフとセル塗りだけで、
マクロもアドインも使いません。

| ブロック | 何が分かるか |
| --- | --- |
| 信号ボード | 欠品リスク／要発注／余裕の品目数と推奨発注額。色の大きさで危険度が先に目に入る |
| 在庫状況の内訳（ワッフル） | 100マスで全体の構成比。赤がどれだけ占めるかが面積で分かる |
| 在庫日数の分布 | どこに山があるか。棒の色が重症度（赤＝切れかけ、緑＝余裕） |
| 商品分類 × 状態 | どの分類が危ないかのヒートマップ。在庫金額はデータバーで大小を表示 |
| 仕入先別 推奨発注額 | どこにいくら発注することになるか |
| 今後14日の入荷予定 | 納品予定日ごとの金額。色が濃い日ほど入荷が集中している |
| 今後14日の動員予測 | 動員計画の数字。山の来る日に在庫が持つかを確かめる |
| 商品の入れ替わり | 新商品・終売候補・マスタ未登録・在庫マイナス・PI値未設定の件数（発注漏れの目印） |

### なぜこの構成にしたか

在庫管理ダッシュボードの定石として、**在庫日数（days of cover）とリードタイムの比較**が
最も行動につながる指標とされています。「在庫日数28日・リードタイム84日」なら、
このままでは56日間欠品する、という読み方ができるためです。
このツールもその考え方を軸に、信号ボードと在庫日数の分布を最上段に置いています。

ワッフルチャートとヒートマップは条件付き書式だけで作れるため、
追加のツールなしにこの表現が使えます。

参考にした資料は README 末尾に挙げています。

## 設計の要点

### 1. 全劇場を1ファイルで持ち、対象劇場を切り替えて使う

在庫CSVは全劇場分をまとめて貼り付けられます。「設定」シートで対象劇場コードを選ぶと、
発注計算とダッシュボードがその劇場のものに切り替わります。劇場横断の状況は「全劇場サマリ」で確認します。

### 2. 劇場の規模差は「規模3段階＋個別上書き」で吸収する

安全在庫日数・発注サイクル・想定来場者数は、規模区分（大/中/小）ごとの標準値を使います。
特定の劇場だけ変えたい場合は定数マスタ①の個別欄に入力すると、そちらが優先されます。
75サイトを1件ずつ設定しなくても、標準3段階で運用を回せます。

### 3. 劇場特性（1杯売り／ドリンクバー）はPIプロファイルで吸収する

PI値（来場者100人あたりの消費数）は**ドリンクの提供方式ごとに2列**だけ持ちます。
PI値は「100人あたり」の数なので、劇場の規模が変わっても値そのものは変わりません
（規模の差は来場者数の側で吸収されます）。商品構成を変えるのは提供方式だけなので、
「1杯売り」「ドリンクバー」の2列で足ります。定数マスタ①で提供方式を選べば自動で切り替わります。

さらに、**発注計算の対象商品は在庫CSVの実データから作られます**。
ドリンクバー方式の劇場ではS/Lカップがそもそも在庫一覧に出てこないため、
取扱商品の違いは設定しなくても自動的に反映されます。

### 4. 期中の商品入れ替えに対応する

当日CSVと2ヶ月前CSVの**和集合**で商品行を作るため、期中に入れ替わった商品も取りこぼしません。
「状態」列で以下を自動判定します。

| 表示 | 意味 |
| --- | --- |
| 新商品 | 当日CSVにあり、2ヶ月前CSVに無い |
| 終売候補 | 2ヶ月前CSVにあり、当日CSVに無い |
| マスタ未登録 | 商品マスタに登録が無い（L/T・ロット・PI値が既定値のまま） |
| 在庫マイナス | 理論値在庫がマイナス（納品の未計上などデータ側のずれ） |
| PI値未設定 | PI値予測基準なのにPI値が空欄 |

### 5. 繁忙期・閑散期の調整

定数マスタ③で月別の係数を設定できます。特定期間だけ変えたい場合は
定数マスタ④「特別期間」に開始日・終了日・係数を登録すると、その期間は月別係数より優先されます
（大型作品の公開週など）。期間が重なる場合は係数が最大の行が使われます。

## 計算式

```
理論値在庫     ＝ 在庫CSVの「総数」（＝在庫数ケース×入数＋在庫数バラ）
当日在庫(採用) ＝ 実棚が入っていればその数、なければ理論値在庫
期間消費数     ＝ 2ヶ月前の在庫 ＋ 期間納品数 － 当日在庫
実績消費/日    ＝ 期間消費数 ÷ 期間日数
PI予測消費/日  ＝ 動員計画のカバー期間の来場者合計 ÷ カバー日数 × PI値 ÷ 100
安全在庫数量   ＝ 採用消費/日 × 安全在庫日数
発注点         ＝ 採用消費/日 ×（リードタイム ＋ 発注サイクル）＋ 安全在庫数量
                 ※ 発注サイクルは商品の発注グループ（定数マスタ⑥）から引く
推奨発注数     ＝ 発注点 － 当日在庫(採用) － 発注残
推奨発注数(ケース) ＝ 推奨発注数 ÷ 入数 を最低ロット単位に切り上げ
```

「採用消費/日」に何を使うかは設定シートの**算出基準**で切り替えます。

| 算出基準 | 採用消費/日 | 想定する使い方 |
| --- | --- | --- |
| **動員連動**（既定） | 実績消費 ×（これからの動員 ÷ 期間の平均動員） | 標準運用 |
| 実績消費 | 在庫2時点の差から算出（動員とは連動しない） | 動員の読みが立たないとき |
| PI値予測 | 来場者予測 × 手入力のPI値 | PI値を自分で決めたいとき |
| 最大値 | 上の3つのうち最大 | 欠品を避けたい繁忙期 |

## 購買率を入力せずに、動員と消費を連動させる

購買率（PI値）は**人が知っている必要も、入力する必要もありません**。
在庫2時点の差と、その期間の平均動員が分かれば、商品ごとの実測PI値は割り算で出るためです。

```
実測PI値       ＝ 実績消費/日 ÷（期間の平均動員/日 ÷ 100）   ← 来場者100人あたりの消費数
動員連動 消費/日 ＝ 実測PI値 × これからの1日あたり動員 ÷ 100
               ＝ 実績消費/日 ×（これからの動員 ÷ 期間の平均動員）
```

分母の「期間の平均動員」は、**動員シートに実績を入れておけば自動で出ます**
（設定シートに手入力の欄もありますが、実績があればそちらが優先されます）。
実績が1日も無い場合は定数マスタ②の標準来場者数が分母になり、動員の増減比だけが効きます。

「これからの動員」は、**その商品の次の発注日までの平均**です。発注サイクルが商品ごとに違うので、
週3回発注の冷凍品は直近の数日だけ、週1回の包材は7日ぶんを見ます。連休の入り方で両者の
見積もりが変わるのは正しい挙動です。

動員計画が全日空欄でも、季節係数（定数マスタ③④）は効きます。GW係数145%なら消費も1.45倍で見積もります。

期間納品数は発注管理シートの「入荷済み」レコードから集計します。
未入荷（発注状況＝発注済）の数量は「発注残」として推奨発注数から差し引かれるため、二重発注を防げます。

## 注意事項

- 数式はすべて INDEX/MATCH・SUMIFS などの旧来関数で記述しています。
  XLOOKUP等の新関数は使っていないため、古いExcelでも動作します。
- 在庫CSVの劇場コードは「0761」のような**先頭ゼロ付きの文字列**です。貼り付け後、
  設定シートの「当日CSV該当行数」が0のままなら、コードが数値に変換されています。
  CSV列を文字列として取り込むか、定数マスタ①のコードを実際の値に合わせてください。
- 在庫CSVはデータを **A6 セル**から貼ります。1〜4行目は案内と取込判定、5行目が見出しです。
- 在庫CSVの受け入れ容量は各10,000行（75劇場×約130商品を想定）です。
  超える場合は `build_workbook.py` の `CSV_LAST` を変更して再生成してください。
- 発注計算・「②発注数を決める」の行数は400商品までです（`CALC_LAST`）。
- 発注書の明細は100行までです。
- 動員計画は当日基準日から90日分です（`PLAN_LAST`）。
- 現行版の刷新設計書に沿った計算エンジン（購買率×イールド）は `build_renewal.py` に
  別ファイルとして残してあります。本ツールとは別物です（`README_renewal.md`）。
- 日付書式に曜日（`aaa`）を使うと環境によっては日付表示が壊れるため、
  日付は `yyyy/m/d` とし、曜日が要る場所は `CHOOSE(WEEKDAY(...))` で別に組み立てています。
- 金額はすべて税抜です。
- 初期の商品マスタはサンプルCSV（132品目）から作成しています。
  L/T日数は3日、最低ロットは1、PI値は空欄が初期値です。運用前に実際の値へ更新してください。
- `売店発注ツール_サンプルデータ入り.xlsx` は3劇場（大規模・1杯売り／中規模・ドリンクバー／
  小規模・1杯売り）ぶんの在庫CSV、90日分の動員計画、発注履歴14件を入れた動作確認用です。
